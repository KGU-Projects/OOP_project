# 프로젝트 기획

## 개요

CODE ESCAPE: CS 퀴즈 기반 2D 퍼즐 플랫포머

옆에서 보는 2D 맵을 달리고 점프하며 탈출하는 학습형 퍼즐 게임이다. 플레이어는 한 명이다. 맵에는 막힌 벽(문)과 버튼이 있고, 버튼을 누르면 CS·자바 개념 퀴즈가 나온다. 퀴즈를 맞히면 벽이 열리고, 틀리면 체력이 깎인다. 각 스테이지에서 열쇠를 얻고, 모든 열쇠를 모으면 보스 스테이지에 입장한다. 보스는 퀴즈를 풀어야 데미지를 줄 수 있고, 빨리 풀수록 데미지가 크다. 변수, 반복문, 조건문, 클래스 등 개념별로 스테이지를 구성한다.

## 목표

- 학습자가 프로그래밍 개념을 게임으로 재미있게 이해하고 복습하게 한다.
- Java Swing으로 캐릭터 이동(중력·점프·충돌), 맵 렌더링, 퀴즈, 화면 전환을 구현한다.
- 클래스 간 상호작용과 상속 등 객체지향 설계 원리를 적용한다. 새 장애물·아이템 종류를 클래스 추가만으로 늘릴 수 있게 한다.
- 문제는 `quiz.txt`, 스테이지는 `data/stages/stageN.txt`, 사용자는 `users.txt`, 세이브는 `data/saves/`의 텍스트 파일로 관리한다. 문제와 스테이지의 추가·수정은 파일을 직접 편집해서 한다.

## 게임 규칙

### 조작

| 키           | 동작                                                 |
| ------------ | ---------------------------------------------------- |
| A, D (←, →)  | 좌우 이동                                            |
| W, Space (↑) | 점프 (바닥에 닿아 있을 때만)                         |
| E            | 가까운 오브젝트(버튼, 열쇠, 아이템, 보스)와 상호작용 |
| 1 ~ 9        | 인벤토리 해당 칸의 아이템 사용                       |
| ESC          | 정지 화면                                            |

### 맵 오브젝트

| 종류     | 동작                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| `BUTTON` | 상호작용하면 퀴즈가 뜬다. 정답이면 연결된 문이 열린다. 한 번 푼 버튼은 다시 쓰지 않는다. |
| `DOOR`   | 막힌 벽. 연결된 버튼의 퀴즈를 맞히기 전까지 통과할 수 없다.                              |
| `KEY`    | 획득하면 열쇠를 얻고 스테이지가 클리어된다.                                              |
| `ITEM`   | 주우면 인벤토리에 들어간다. 지금은 체력 포션이며, 종류는 추후 추가한다.                  |
| `BOSS`   | 보스 스테이지에만 있다. 상호작용하면 퀴즈가 뜨고, 정답이면 보스에게 데미지를 준다.       |

### 퀴즈와 체력

- 퀴즈를 틀리면 체력이 깎인다. 맵의 함정이나 적으로는 피해를 입지 않는다.
- 일반 퀴즈는 틀려도 같은 퀴즈에 다시 도전할 수 있다. 퀴즈 화면에서 취소하면 맵으로 돌아가고 페널티는 없다.
- 체력 포션을 사용하면 체력이 회복된다. 최대 체력을 넘지 않는다.

### 스테이지와 보스

- 스테이지는 번호 순서로 진행한다. 일반 스테이지의 열쇠를 얻으면 스테이지가 클리어되고 다음 스테이지로 간다.
- 모든 일반 스테이지의 열쇠를 모으면 보스 스테이지에 입장한다.
- 보스는 체력이 있고, 보스 스테이지의 퀴즈를 하나씩 낸다. 정답이면 `풀이 시간`에 따라 데미지를 준다.

  ```
  데미지 = 최대 데미지 - 풀이 초 × 초당 감소량   (최소 데미지 미만으로 내려가지 않는다)
  ```

- 풀이 시간은 퀴즈 화면이 뜬 순간부터 정답을 제출한 순간까지다. 오답이면 체력이 깎이고 시간은 계속 흐른다.
- 보스 체력이 0이 되면 게임 클리어다.

### 체력 0 (게임 오버)

체력이 0이 되면 선택 화면이 나온다.

- **처음부터 시작**: 현재 스테이지의 시작 지점에서 다시 시작한다. 체력은 최대로 채우고, 점수와 인벤토리는 스테이지 입장 시점으로 되돌린다. 열린 문과 푼 버튼, 주운 아이템도 초기화된다.
- **마지막 저장 위치에서 시작**: 이번 게임에서 마지막으로 저장하거나 불러온 슬롯의 저장 상태로 돌아간다. 저장한 슬롯이 없으면 이 선택지는 비활성화된다.

### 점수

점수 값은 상수로 두고 팀이 조정한다. 초기안은 아래와 같다.

- 퀴즈 정답: +100
- 보스에게 준 데미지: 데미지 값만큼 가산
- 스테이지 클리어(열쇠 획득): +500

## 화면 흐름

1. 시작 화면에서 시작, 불러오기, 점수판, 종료를 선택한다.
2. 시작을 누르면 초기설정 화면에서 닉네임을 입력한다. `users.txt`에 사용자가 추가되고 1스테이지로 새 게임을 시작한다.
3. 불러오기를 누르면 사용자 목록이 나오고, 사용자를 고르면 그 사용자의 저장 슬롯 목록이 나온다. 슬롯을 고르면 저장된 상태로 이어서 시작한다.
4. 메인게임에서 이동하고 오브젝트와 상호작용한다. 퀴즈가 필요한 오브젝트와 상호작용하면 퀴즈 화면이 뜨고, 끝나면 메인게임으로 돌아온다.
5. 체력이 0이 되면 게임 오버 화면에서 "처음부터 시작"과 "마지막 저장 위치에서 시작" 중 하나를 고른다.
6. ESC를 누르면 정지 화면으로 가며, 계속하기, 저장(슬롯 선택), 시작 화면으로 나가기를 고른다. 저장하면 `data/saves/<닉네임>/slotN.txt`가 갱신된다.
7. 스테이지를 클리어하면 최고점수와 클리어 수를 갱신한다. 보스를 쓰러뜨리면 엔딩 화면에서 최종 점수를 보여 주고, 순위 화면에 반영된다.

## 일정

| 기간    | 내용                                                                                        |
| ------- | ------------------------------------------------------------------------------------------- |
| 1주차   | 기획 확정, 데이터 형식과 화면 설계, 기본 구조 구현 (화면 전환, 중력·점프·충돌이 되는 이동)  |
| 2주차   | 맵 렌더링, 오브젝트(버튼·문·열쇠)와 퀴즈 연동, 스테이지 파일 입출력(문제, 스테이지, 사용자) |
| 3주차   | 체력·아이템·게임 오버, 보스 스테이지와 속도 데미지, 세이브 슬롯 저장·불러오기, 순위         |
| 4주차   | 통합 테스트, 버그 수정, 최종 점검, 발표 준비 및 중간 발표                                   |
| 5~6주차 | 발표 피드백 반영, 스테이지·문제 추가, 새 오브젝트 종류 확장, 최종 제출                      |

m# 구현 순서

1. 계약 확정: model, repository 인터페이스, `Screen`, `ScreenType`, `ScreenManager`, 빈 화면 클래스로 화면 전환만 되는 상태를 `main`에 올린다.
2. 병렬 개발: 각자 담당 영역을 구현한다. 파일 입출력 전에는 `InMemory...Repository`를 쓴다.
3. 통합: `GameApp`에서 파일 구현체로 교체하고 전체 흐름을 테스트한다.
