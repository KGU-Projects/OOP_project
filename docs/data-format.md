# 데이터 파일 형식

## 파일 구성

```
data/
  users.txt              사용자 목록 (Git 제외)
  quiz.txt               문제
  stages/
    stage1.txt           스테이지당 파일 하나
    stage2.txt
    ...
  saves/                 세이브 (Git 제외)
    <닉네임>/
      slot1.txt          슬롯당 파일 하나
      slot2.txt
      slot3.txt
```

## 한눈에 보기

### 파일 사이의 연결

파일들은 이름이나 ID로 서로를 가리킨다. 아래 화살표가 "이 값으로 저 파일을 찾는다"는 뜻이다.

```
users.txt
  태호|1200|2|...
   │
   │ 닉네임 = 세이브 폴더 이름
   ▼
saves/태호/slot1.txt
  3|12.50|3.40|4|700|...
   │
   │ 첫 칸 = 스테이지 번호
   ▼
stages/stage3.txt
  b1|BUTTON|3|4|7|d1        ← 버튼 b1은 7번 문제를 내고, 맞히면 문 d1을 연다
   │            │    │
   │            │    └────── 문 ID: 같은 파일 안의 d1|DOOR|... 줄
   │            └─────────── 문제ID: quiz.txt의 7번 줄
   ▼
quiz.txt
  7|3|CHOICE|for 문 ...
```

- 사용자와 세이브는 **닉네임**으로, 세이브와 스테이지는 **스테이지 번호**로, 버튼과 퀴즈는 **문제ID**로, 버튼과 문은 **오브젝트 ID**로 연결된다.
- 퀴즈와 문제는 서로를 모른다. 연결 정보는 스테이지 파일의 `BUTTON` 줄에만 있다.

### 이 문서의 예시 이야기

아래 예시는 모두 같은 장면을 가리킨다. 한 번 읽어 두면 파일마다 값이 이어진다.

> 사용자 **태호**는 1, 2스테이지를 클리어했고 지금 **3스테이지(반복문의 방)** 를 하고 있다.
> 버튼 `b1`, `b2`의 퀴즈를 풀어 문 `d1`, `d2`를 모두 열었고, 포션 `p1`을 주웠다.
> 퀴즈를 두 개 맞혀 점수는 입장 때보다 200점 오른 700점이고, 오답을 한 번 내서 체력은 5 중 4다.
> 아직 열쇠 `k3`는 얻지 못했다. 이 상태를 슬롯 1에 저장했다.

## 공통 규칙

- 인코딩은 UTF-8이며, 읽고 쓸 때 명시한다.
- 필드 구분자는 `|`이고 `split("\\|", -1)`로 읽는다.
  - `split("|")`는 정규식 때문에 잘못 잘린다.
  - `-1`이 없으면 끝의 빈 필드가 사라진다.
- 필드 안의 목록: 보기는 `~`, ID 목록은 `,`로 구분한다. 인벤토리는 `종류:개수`를 `,`로 이어 쓴다.
- 문제·해설 안의 줄바꿈은 `\n` 두 글자로 저장하고, 읽을 때 실제 줄바꿈으로 바꾼다.
- 사용자 입력에서 `|`는 허용하지 않는다.
- 수정 시에는 전체를 읽어 리스트로 만들고, 고친 뒤, 전체를 다시 쓴다.
- 소수 숫자는 `Locale.ROOT`로 읽고 쓴다. 로케일에 따라 `,`가 소수점이 되면 안 된다.
- 파일 경로는 상수로 관리한다.
- 형식이 맞지 않으면 파일 이름과 줄 번호를 포함한 예외(`DataFormatException`)를 던진다.

## users.txt (한 줄 = 사용자 1명)

순서: `닉네임 | 최고점수 | 클리어한 스테이지 수 | 마지막 플레이 일시`

```
태호|1200|2|2026-11-01 14:30
새유저|0|0|2026-11-01 15:00
```

- 진행 상태(스테이지, 위치, 체력 등)는 이 파일에 두지 않고 세이브 파일에 둔다.
- 닉네임이 키다. 중복 불가. 1~12자의 한글, 영문, 숫자만 허용한다. 세이브 폴더 이름으로 쓰기 때문이다.
- 일시 형식은 `yyyy-MM-dd HH:mm`이다.
- 파일이 없으면 빈 파일을 생성한다. Git에는 올리지 않고 `users.sample.txt`를 예시로 둔다.

### 예시 해설: `태호|1200|2|2026-11-01 14:30`

| 순서 | 값                 | 모델 필드 (`User`)       | 뜻                                                                     |
| ---- | ------------------ | ------------------------ | ---------------------------------------------------------------------- |
| 1    | `태호`             | `nickname`               | 사용자 이름이자 키. `data/saves/태호/` 폴더 이름이 된다.               |
| 2    | `1200`             | `highScore`              | 지금까지 어느 플레이에서든 기록한 **최고** 점수. 순위 화면에 쓰인다.   |
| 3    | `2`                | `clearedStages`          | 클리어한 스테이지 누적 수.                                             |
| 4    | `2026-11-01 14:30` | `lastPlayedAt`           | 마지막으로 플레이한 시각.                                              |

메모리에서는 이렇게 된다.

```
User { nickname="태호", highScore=1200, clearedStages=2, lastPlayedAt=2026-11-01T14:30 }
```

최고점수 `1200`과 세이브의 현재 점수 `700`은 다른 값이다. 최고점수는 사용자에게, 현재 점수는 지금 하는 플레이(세이브)에 속한다.

## saves/<닉네임>/slotN.txt (한 줄 = 저장 상태 1개)

슬롯 번호는 파일 이름이 정한다. 슬롯 수는 상수(`SAVE_SLOT_COUNT`, 초기값 3)이고, 파일이 없는 슬롯은 빈 슬롯이다.

순서: `스테이지 번호 | x | y | 체력 | 점수 | 인벤토리 | 보유 열쇠 | 열린 문ID | 푼 오브젝트ID | 획득 오브젝트ID | 보스 체력 | 스테이지 입장 시 점수 | 스테이지 입장 시 인벤토리 | 저장 일시`

```
3|12.50|3.40|4|700|HEALTH_POTION:2|1,2|d1,d2|b1,b2|p1|-1|500|HEALTH_POTION:1|2026-11-01 14:30
```

- `x`, `y`: 플레이어 위치. 타일 단위 실수이고 소수 둘째 자리까지 쓴다.
- `보유 열쇠`: 획득한 열쇠가 속한 스테이지 번호 목록이다.
- `열린 문ID`, `푼 오브젝트ID`, `획득 오브젝트ID`: 저장 시점의 현재 스테이지 안에서의 오브젝트 ID다. 스테이지가 바뀌면 비운다.
- `보스 체력`: 보스 스테이지에서만 의미가 있고, 그 외에는 `-1`이다.
- `스테이지 입장 시 점수/인벤토리`: 게임 오버 후 "처음부터 시작"에서 되돌릴 값이다.
- 목록이 비면 빈 칸으로 둔다. 인벤토리 종류 이름은 `ItemType` 이름과 같다.
- 세이브 폴더는 처음 저장할 때 만든다. Git에는 올리지 않는다.

### 예시 해설

위 한 줄을 칸별로 풀면 다음과 같다. 모델 필드는 `SaveData`의 필드다.

| 순서 | 값                  | 모델 필드                 | 뜻                                                                                   |
| ---- | ------------------- | ------------------------- | ------------------------------------------------------------------------------------ |
| 1    | `3`                 | `stageNo`                 | 3스테이지에서 저장했다. 이어하기 때 `stages/stage3.txt`를 읽는다.                    |
| 2    | `12.50`             | `x`                       | 왼쪽에서 12.5타일 지점.                                                              |
| 3    | `3.40`              | `y`                       | 위에서 3.4타일 지점. 바닥 줄(5)에 서 있는 높이다. (5 − 키 1.6 = 3.4)                 |
| 4    | `4`                 | `hp`                      | 현재 체력. 최대 체력(`MAX_HP`=5)은 저장하지 않고 상수에서 가져온다.                  |
| 5    | `700`               | `score`                   | 이번 플레이의 현재 점수.                                                             |
| 6    | `HEALTH_POTION:2`   | `inventory`               | 체력 포션 2개를 갖고 있다. 두 종류면 `HEALTH_POTION:2,다른아이템:1`처럼 이어 쓴다.   |
| 7    | `1,2`               | `keys`                    | 1스테이지와 2스테이지의 열쇠를 갖고 있다. 3스테이지 열쇠는 아직 없다.                |
| 8    | `d1,d2`             | `openedDoorIds`           | 이 스테이지의 문 `d1`, `d2`가 열려 있다.                                             |
| 9    | `b1,b2`             | `solvedObjectIds`         | 버튼 `b1`, `b2`의 퀴즈를 이미 풀었다. 다시 누를 수 없다.                            |
| 10   | `p1`                | `collectedObjectIds`      | 아이템 `p1`을 주웠다. 맵에 다시 나타나지 않는다.                                     |
| 11   | `-1`                | `bossHp`                  | 보스 스테이지가 아니므로 의미 없음.                                                  |
| 12   | `500`               | `stageEntryScore`         | 3스테이지에 들어올 때의 점수. 지금은 700이니 이 스테이지에서 200점을 얻었다.         |
| 13   | `HEALTH_POTION:1`   | `stageEntryInventory`     | 입장할 때 포션이 1개였다. 지금 2개이니 `p1`로 1개를 얻었다.                          |
| 14   | `2026-11-01 14:30`  | `savedAt`                 | 저장한 시각. 슬롯 목록 화면에 표시한다.                                              |

세이브 안의 숫자들은 서로 맞아야 한다. 예시에서는 퀴즈 2개 정답(+100 × 2)이 점수 차이 200과 같고, 열린 문이 풀린 버튼과 같은 개수이며, 주운 `p1`이 포션 1→2개와 맞는다.

목록이 빈 칸으로 저장된 예는 4스테이지에 막 입장한 직후의 저장이다. 열린 문, 푼 오브젝트, 획득 오브젝트가 없으므로 8~10번째 칸이 비어 `||||`처럼 보인다. 14칸을 항상 모두 쓴다.

```
4|1.10|3.40|5|800|HEALTH_POTION:2|1,2,3||||-1|800|HEALTH_POTION:2|2026-11-02 09:10
```

메모리에서는 이렇게 된다.

```
SaveData {
  stageNo=3, x=12.5, y=3.4, hp=4, score=700,
  inventory={HEALTH_POTION=2},
  keys={1, 2},
  openedDoorIds={"d1","d2"}, solvedObjectIds={"b1","b2"}, collectedObjectIds={"p1"},
  bossHp=-1,
  stageEntryScore=500, stageEntryInventory={HEALTH_POTION=1},
  savedAt=2026-11-01T14:30
}
```

## quiz.txt (한 줄 = 문제 1개)

순서: `문제ID | 스테이지 | 유형 | 문제 | 보기(~ 구분) | 정답 | 해설`

```
1|1|CHOICE|int형 변수 선언으로 올바른 것은?|int a = 3;~a int = 3;~int: a = 3;~var int a;|1|int 뒤에 변수명을 씁니다.
2|1|INPUT|정수형 변수를 선언할 때 쓰는 키워드는?||int|기본형 중 정수는 int입니다.
7|3|CHOICE|for (int i = 0; i < 3; i++)가 반복하는 횟수는?|2번~3번~4번~무한|2|i가 0, 1, 2일 때 참이므로 3번 반복합니다.
8|3|INPUT|조건이 참인 동안 반복하는 키워드는?||while|while은 조건식이 참인 동안 본문을 반복합니다.
30|5|CHOICE|배열의 첫 번째 인덱스는?|0~1~-1~지정할 수 없음|1|자바 배열의 인덱스는 0부터 시작합니다.
```

- 유형: `CHOICE`(객관식), `INPUT`(입력형)
- 객관식 정답은 보기 번호(1부터), 입력형 정답은 문자열이다. 입력형의 보기 칸은 비운다.
- 입력형은 앞뒤 공백 제거, 대소문자 무시 후 비교한다.
- 문제는 앱이 아니라 이 파일을 직접 편집해서 추가·수정·삭제한다.
- 문제ID는 재사용하지 않는다. 새 문제는 최대 ID + 1을 쓴다. (위 예시처럼 ID가 연속일 필요는 없다.)
- 일반 스테이지의 퀴즈는 `BUTTON` 오브젝트가 문제ID로 참조한다. 문제를 삭제하거나 ID를 바꾸기 전에 `stages/` 안의 어떤 `BUTTON`이 그 문제ID를 쓰는지 확인한다.
- 보스 스테이지는 문제ID로 참조하지 않는다. `스테이지` 칸이 보스 스테이지 번호인 문제 전부가 보스의 문제 풀이다.

### 예시 해설

**객관식**: `7|3|CHOICE|for (int i = 0; i < 3; i++)가 반복하는 횟수는?|2번~3번~4번~무한|2|...`

| 순서 | 값                              | 모델 필드                  | 뜻                                                              |
| ---- | ------------------------------- | -------------------------- | --------------------------------------------------------------- |
| 1    | `7`                             | `Quiz.id`                  | 문제 번호. 스테이지 파일의 `BUTTON ... 7 ...`이 이 값을 가리킨다. |
| 2    | `3`                             | `Quiz.stageNo`             | 3스테이지용 문제. (보스 문제 풀을 고를 때 이 값을 쓴다.)        |
| 3    | `CHOICE`                        | `getType()`                | 이 값으로 `ChoiceQuiz`가 만들어진다.                            |
| 4    | `for (...)가 반복하는 횟수는?`  | `Quiz.question`            | 화면에 보이는 문제.                                             |
| 5    | `2번~3번~4번~무한`              | `ChoiceQuiz.choices`       | `~`로 나눈 보기 4개.                                            |
| 6    | `2`                             | `ChoiceQuiz.answerNo`      | 정답은 **2번째 보기**(`3번`). 0이 아니라 1부터 센다.            |
| 7    | `i가 0, 1, 2일 때 ...`          | `Quiz.explanation`         | 채점 후 보여 주는 해설.                                         |

**입력형**: `8|3|INPUT|조건이 참인 동안 반복하는 키워드는?||while|...`

- 보기 칸(5번째)이 비어 있다. `||`처럼 `|`가 연달아 나오는 것이 비어 있다는 표시다. 이 줄은 `split("\\|", -1)`로 읽어야 빈 칸이 사라지지 않고 7칸이 모두 나온다.
- 정답 `while`은 `InputQuiz.answer`가 된다. 사용자가 ` While `이라고 입력해도 정답이다.

메모리에서는 이렇게 된다.

```
ChoiceQuiz { id=7, stageNo=3, question="for (int i = 0; ...)", choices=["2번","3번","4번","무한"], answerNo=2, explanation="..." }
InputQuiz  { id=8, stageNo=3, question="조건이 참인 동안 ...", answer="while", explanation="..." }

quiz.isCorrect("2")      → true   (ChoiceQuiz: 입력 번호가 answerNo와 같다)
quiz.isCorrect("3")      → false
quiz.isCorrect(" While ") → true   (InputQuiz: 공백 제거, 대소문자 무시)
```

`30|5|CHOICE|...`은 보스 스테이지(5번) 문제다. 어떤 버튼도 이 ID를 가리키지 않고, 보스가 `stageNo=5`인 문제를 골라 낸다.

## stages/stageN.txt (한 파일 = 스테이지 1개)

파일 이름의 `N`은 정보 줄의 번호와 같아야 한다. 스테이지 목록은 `data/stages/`의 `stage*.txt`를 번호 순으로 읽어 만든다.

```
3|반복문의 방|반복문|NORMAL|0|20|6
####################
#..................#
#..................#
#....###...........#
#P.................#
####################
6
b1|BUTTON|3|4|7|d1
p1|ITEM|6|2|HEALTH_POTION|1
d1|DOOR|9|1|4
b2|BUTTON|12|4|8|d2
d2|DOOR|15|1|4
k3|KEY|18|4
```

### 블록 순서

1. 정보 한 줄: `번호 | 제목 | 학습 개념 | 유형 | 테마 | 가로 | 세로`
   - 유형: `NORMAL`(일반), `BOSS`(보스). 보스 스테이지는 하나이고 번호가 가장 크다.
   - 테마: 배경·타일 이미지를 고르는 번호. 이미지가 없는 동안은 `0`을 쓴다.
2. 지형: 세로 값만큼의 줄. 각 줄의 길이는 가로 값이다.
3. 오브젝트 개수 한 줄
4. 오브젝트: 개수만큼 한 줄씩

섹션 헤더 없이 개수 정보로 읽을 줄 수를 정한다.

### 지형 문자

| 문자 | 의미                                    |
| ---- | --------------------------------------- |
| `#`  | 단단한 블록 (벽, 바닥, 발판). 통과 불가 |
| `.`  | 빈 공간                                 |
| `P`  | 플레이어 시작 위치 (빈 공간으로 취급)   |

지형은 변하지 않는 타일만 그린다. 문, 버튼, 아이템 같은 것은 오브젝트로 적는다.

### 좌표

- 왼쪽 위가 `(0, 0)`이고, x는 오른쪽, y는 아래로 늘어난다. 단위는 타일이다.
- 오브젝트 좌표는 오브젝트의 왼쪽 위 타일이다.
- 플레이어 시작 위치는 `P` 타일에 서 있는 좌표로 바꿔 쓴다. `P`가 `(tx, ty)`이면 `x = tx + (1 − 폭) / 2`, `y = ty + 1 − 키`이다. (폭 0.8, 키 1.6이면 위 예시의 `P(1, 4)`는 `x=1.10, y=3.40`이 된다.)

### 오브젝트 줄

공통 앞부분: `ID | 종류 | x | y`, 그 뒤에 종류별 세부값이 `|`로 이어진다.

| 종류     | 세부값                      | 설명                                                  |
| -------- | --------------------------- | ----------------------------------------------------- |
| `BUTTON` | `문제ID \| 열 문ID 목록(,)` | 퀴즈를 맞히면 목록의 문이 열린다.                     |
| `DOOR`   | `높이(타일 수)`             | 폭 1타일, 아래로 높이만큼 막는다. 처음에는 닫혀 있다. |
| `KEY`    | (없음)                      | 획득하면 스테이지 클리어                              |
| `ITEM`   | `아이템 종류 \| 개수`       | 예: `HEALTH_POTION`                                   |
| `BOSS`   | `보스 이름 \| 최대 체력`    | 보스 스테이지에만 둔다.                               |

- 오브젝트 ID는 한 스테이지 안에서 유일해야 한다. 영문, 숫자, `_`만 쓴다.
- 새 종류를 추가해도 파일 구조는 바뀌지 않는다. 세부값 칸만 늘어난다. 종류 문자열을 객체로 바꾸는 코드는 `FileStageRepository`의 팩토리 메서드 한 곳에만 둔다.
- 알 수 없는 종류, 존재하지 않는 문제ID나 문 ID를 참조하는 경우, 범위를 벗어난 좌표는 줄 번호를 포함한 예외를 던진다. (문제ID 존재 여부는 `quiz.txt`를 읽는 쪽에서 검증한다.)
- 일반 스테이지에는 `KEY`가 정확히 하나, 보스 스테이지에는 `BOSS`가 정확히 하나 있어야 한다.

### 예시 해설: 이 파일이 만드는 맵

지형 줄(글자 격자)과 오브젝트 줄을 겹치면 아래 그림이 된다. 이 그림은 파일에 적지 않고, **스테이지 미리보기 도구**(`tool/StagePreviewMain`, 사용법은 `architecture.md`)가 파일을 읽어 이 모양으로 출력한다. (`B` 버튼, `D` 문, `I` 아이템, `K` 열쇠, `P` 시작) 파일의 격자에는 `#`, `.`, `P`만 쓸 수 있다.

```
      x: 01234567890123456789
 y=0     ####################
 y=1     #........D.....D...#      D(d1)과 D(d2)는 y=1부터 4칸 높이로 복도를 막는다
 y=2     #.....I..D.....D...#      I(p1)는 발판 위에 놓인 포션
 y=3     #....###.D.....D...#      ### 는 지형의 발판(x=5~7)
 y=4     #P.B.....D..B..D..K#      B(b1) → D(d1), B(b2) → D(d2), K(k3)는 끝에 있다
 y=5     ####################
```

플레이어는 `P`에서 출발해 `b1`을 눌러 7번 문제를 풀면 `d1`이 열리고, 지나가서 `b2`로 8번 문제를 풀면 `d2`가 열리며, 열쇠 `k3`를 얻으면 스테이지가 끝난다. 포션 `p1`은 발판 위에 있어서 점프해야 닿는다.

**정보 줄**: `3|반복문의 방|반복문|NORMAL|0|20|6`

| 값           | 모델 필드 (`Stage`)  | 뜻                                      |
| ------------ | -------------------- | --------------------------------------- |
| `3`          | `number`             | 3스테이지. 파일 이름 `stage3.txt`와 같다. |
| `반복문의 방` | `title`              | 화면에 표시하는 제목.                   |
| `반복문`     | `concept`            | 이 스테이지가 가르치는 개념.            |
| `NORMAL`     | `type`               | 일반 스테이지. 보스 스테이지는 `BOSS`.  |
| `0`          | `theme`              | 배경 테마. 아직 이미지가 없어 0.        |
| `20`, `6`    | `width`, `height`    | 가로 20칸, 세로 6칸. 아래 지형 줄이 6줄, 각 줄이 20글자여야 한다. |

**지형 줄**: 6줄이 `Tile[6][20]` 배열이 된다. `#`는 `Tile.SOLID`, `.`은 `Tile.EMPTY`, `P`는 `EMPTY`로 바뀌고 위치만 기억한다.

**오브젝트 줄**: 한 줄이 한 객체가 된다. 앞 4칸은 공통이고 나머지는 종류마다 다르다.

| 파일의 줄                    | 만들어지는 객체                                                       | 뜻                                                          |
| ---------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------- |
| `b1\|BUTTON\|3\|4\|7\|d1`    | `ButtonObject(id="b1", x=3, y=4, quizId=7, doorIds=["d1"])`           | (3,4)의 버튼. 누르면 7번 문제, 정답이면 `d1`을 연다.        |
| `p1\|ITEM\|6\|2\|HEALTH_POTION\|1` | `ItemObject(id="p1", x=6, y=2, itemType=HEALTH_POTION, count=1)` | (6,2)의 포션 1개. 주우면 인벤토리에 +1.                     |
| `d1\|DOOR\|9\|1\|4`          | `DoorObject(id="d1", x=9, y=1, height=4)`                             | (9,1)부터 아래로 4칸을 막는 문. 열리기 전엔 통과 불가.      |
| `b2\|BUTTON\|12\|4\|8\|d2`   | `ButtonObject(id="b2", x=12, y=4, quizId=8, doorIds=["d2"])`          | 두 번째 버튼. 8번 문제, 정답이면 `d2`를 연다.               |
| `d2\|DOOR\|15\|1\|4`         | `DoorObject(id="d2", x=15, y=1, height=4)`                            | 두 번째 문.                                                 |
| `k3\|KEY\|18\|4`             | `KeyObject(id="k3", x=18, y=4)`                                       | 열쇠. 얻으면 이 스테이지가 클리어된다.                      |

버튼 하나가 문 여러 개를 열려면 `b1|BUTTON|3|4|7|d1,d2`처럼 문 ID를 `,`로 이어 쓴다.

**보스 스테이지 예시**: 같은 형식이고 유형과 오브젝트만 다르다.

```
5|최종 보스|종합|BOSS|0|20|8
(지형 8줄)
1
boss1|BOSS|16|5|버그 드래곤|300
```

`BossObject(id="boss1", x=16, y=5, name="버그 드래곤", maxHp=300)`이 만들어진다. 퀴즈는 오브젝트 줄이 아니라 `quiz.txt`에서 `스테이지=5`인 문제 전부가 풀이다. 정답을 4초 만에 제출하면 `100 − 4 × 5 = 80`의 데미지를 주고(초기 상수 기준), 보스 체력은 `300 → 220`이 된다.

## 파일에 저장되지 않는 모델 (실행 중에만 존재)

파일 하나하나는 정적인 정의이고, 게임을 하는 동안에는 이것들이 `GameState` 하나로 합쳐진다. 위 세이브 `slot1.txt`를 불러오면 `GameState`가 아래처럼 채워진다.

```
GameState
 ├ user                = User("태호", 최고 1200, 클리어 2)          ← users.txt
 ├ stage               = Stage #3 "반복문의 방"                      ← stages/stage3.txt (오브젝트 6개 포함)
 ├ player              = Player(x=12.5, y=3.4, hp=4/5,               ← slot1.txt의 위치·체력·인벤토리
 │                        inventory={HEALTH_POTION=2})
 ├ status              = PLAYING
 ├ score               = 700
 ├ keys                = {1, 2}
 ├ openedDoorIds       = {d1, d2}
 ├ solvedObjectIds     = {b1, b2}
 ├ collectedObjectIds  = {p1}
 ├ bossHp              = -1
 ├ currentSlot         = 1            ← "마지막 저장 위치에서 시작"이 이 슬롯을 다시 불러온다
 ├ stageEntryScore     = 500
 └ stageEntryInventory = {HEALTH_POTION=1}
```

화면에는 이렇게 보인다. 오브젝트 자체는 바뀌지 않고, `GameState`의 ID 집합을 보고 판단한다.

| 오브젝트 | 상태 집합                       | 화면과 동작                                  |
| -------- | ------------------------------- | -------------------------------------------- |
| `d1`, `d2` | `openedDoorIds`에 있음        | 열린 문으로 그려지고 통과할 수 있다.         |
| `b1`, `b2` | `solvedObjectIds`에 있음      | 눌린 버튼으로 그려지고 E를 눌러도 퀴즈가 안 뜬다. |
| `p1`     | `collectedObjectIds`에 있음     | 그려지지 않는다.                             |
| `k3`     | 어느 집합에도 없음              | 열쇠가 그려지고, 닿아서 E를 누르면 클리어된다. |

**실행 중 결과 객체**

```
interact()가 돌려주는 InteractionResult
  버튼 b1 (미해결)         → QUIZ(quizId=7)
  버튼 b1 (이미 해결)      → NONE
  열쇠 k3                  → STAGE_CLEARED
  포션 p1                  → PICKED_UP
  보스 boss1               → BOSS_QUIZ

submitAnswer()가 돌려주는 AnswerResult
  7번 문제, 정답           → AnswerResult { correct=true,  gainedScore=100, damageTaken=0, playerDead=false }
  7번 문제, 오답 (체력 4)  → AnswerResult { correct=false, gainedScore=0,   damageTaken=1, playerDead=false }
  오답, 체력 1일 때        → AnswerResult { correct=false, damageTaken=1, playerDead=true }   → GAME_OVER
  보스, 4초에 정답         → AnswerResult { correct=true,  bossDamage=80, gainedScore=80, bossDefeated=false }
```

`damageTaken`, `gainedScore`, 보스 데미지 값은 `architecture.md`의 상수 초기안 기준이다.
