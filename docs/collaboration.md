# 협업 규칙

## 팀 규칙

1. 코드는 Git(GitHub)으로 관리한다.
2. 회의 시간 등 약속한 시간을 지킨다. 늦거나 불참할 경우 사전에 팀 채팅방에 알린다.
3. 맡은 역할에 최선을 다하고, 진행이 막히면 바로 공유한다.
4. AI로 작성된 코드는 그대로 올리지 않는다. 내용을 이해하고 직접 검수·테스트한 뒤에 푸시한다.
5. 코드 포맷은 `CLAUDE.md`의 필수 규칙을 따른다. 파일 인코딩은 UTF-8이다.

## Git 규칙

- `main`에 직접 푸시하지 않는다. 기능별 브랜치에서 작업하고 Pull Request로 합친다.
- 브랜치 이름: `feature/기능명`, `fix/버그명` (예: `feature/quiz-screen`)
- PR은 다른 팀원 한 명 이상이 확인한 뒤 머지한다. AI 코드 검수도 이 단계에서 확인한다.
- 작업 시작 전에 `main`을 pull 받고, 커밋은 작게 자주 한다.
- 커밋 메시지는 한 일을 한 줄로 쓴다. (예: `퀴즈 화면 객관식 보기 표시 구현`)

## 충돌 방지

- model, repository 인터페이스, `Screen`, `ScreenType`은 팀 합의로 먼저 확정하고, 이후 변경도 합의 후에만 한다.
- 각자 담당 패키지와 파일만 수정한다. 다른 사람의 파일을 고쳐야 하면 담당자에게 먼저 알린다.
- `GameApp`은 담당자 한 명이 관리한다.
- `GameObject`, `ItemType`처럼 종류를 늘리는 클래스나 enum도 공유 계약이다. 새 종류를 추가하는 사람이 `data-format.md`의 오브젝트 표도 함께 고친다.
- `quiz.txt`와 `data/stages/`의 스테이지 파일은 데이터 담당자만 수정한다.
- IDE 설정 파일, 빌드 결과물, `data/users.txt`, `data/saves/`는 Git에 올리지 않는다. (`.gitignore`, `.gitattributes` 참고)

## 패키지와 경로

- 기본 패키지는 `io.github.OOP_project`이고 소스는 `src/io/github/OOP_project/`에 있다. 패키지 구조는 `architecture.md`를 따른다.
- 새 패키지를 만들거나 클래스의 위치를 옮길 때는 먼저 팀에 알린다.
